# Prompt and data trust boundaries

Rumor Mill treats every model call as a boundary between trusted application policy and data that
may be adversarial. This applies even when the data was committed by an author or generated by an
earlier model.

## Trust model

| Input | Trust | Handling |
| --- | --- | --- |
| Fixed application policy | Trusted | Supplied only by version-controlled engine code as the system message. |
| World files and character state | Untrusted data | Serialized into one scoped developer payload; strings have no instructional authority. |
| Visitor text and quoted material | Untrusted data | Placed only in a fenced user message and explicitly labeled as dialogue. |
| Previous model output | Untrusted data | Parsed into strict schemas, scoped to one visitor, and revalidated before persistence or display. |
| Operator actions | Privileged but fallible | Authenticated separately; never embedded as conversational policy. |
| Logs and reports | Restricted diagnostics | Record opaque references and stable error codes, not prompts, secrets, or private dialogue. |

## Conversation defenses

Conversation context contains only one character, one run, and one visitor relationship. Repository
queries enforce visitor ownership before that context is constructed. The provider must return a
strict structured response. Before any response is streamed or committed, the engine rejects:

- memory and claim references outside the scoped context;
- verbatim disclosure of claims marked protected for the turn;
- instruction-extraction and role-confusion markers in reply, action, or proposed memory fields.

A rejected generation commits neither the visitor message nor model output. The player receives a
neutral in-world-safe explanation, while operators receive `conversation_safety_blocked` with the
conversation/run references and a stable `safety_code`. Raw prompts and generated text are omitted.

## Adversarial verification

Tests cover visitor prompt extraction, authored strings that resemble role instructions, protected
canon disclosure, leakage through proposed memories, out-of-scope IDs, and cross-visitor access.
These deterministic checks complement the narrative evaluation suite and must run without a paid
model provider.
